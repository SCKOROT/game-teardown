# 输出模板（模块化）

模板不是一套固定章节，而是 **必含骨架 + 按品类挂载的维度块**。先按 `by-genre.md` 定品类，再决定挂哪些块、砍哪些块。核心原则：**买断制 / 叙事向游戏不要硬写 F2P 商业化与经济水池**——硬写就是凑数，反而暴露"拿手游模型套一切"的外行感。

---

## 一、必含骨架（任何品类都要有）

> 篇幅锚点：全面拆解（full）约 **2000–4000 字**。

```markdown
# 《游戏名》拆解报告
> 版本/平台 · 拆解范围 · 拆解深度 · 拆解人 · 日期

## 一、速览（30 秒结论）
- 一句话定位：它是什么品类、给谁玩、靠什么留住人 / 靠什么（或是否）赚钱
- 设计上最值得学的 1–3 个点（先抛结论，钩住读者）

## 二、核心循环
- 一张 mermaid 闭环图画出核心循环：[行动]→[反馈/产出]→[成长/变化]→[新目标]（图模板见 diagrams.md）
- 这个循环靠什么驱动重复？爽点和动力来自哪？
- 次级循环（日/周/赛季 或 关卡/章节）如何叠加在核心循环之上

## 三、系统结构
- 一张 mermaid 依赖图表现系统关系（箭头标资源/动力流向，模板见 diagrams.md）
- 主要系统清单，以及每个系统挂在循环的哪一环、解决什么问题
- 系统间如何咬合/制衡（哪个产出喂给哪个消耗）

## 四、设计支柱（必含）
- 点名这款游戏最用力、最差异化的 2–3 个**设计支柱**——判据：抽掉它游戏还成立吗？抽掉就垮的才是支柱（见 universal-framework.md）。
- 支柱决定下文挂载块的深浅：**支柱所在维度深拆，其余略写**。这一段是"深拆支柱、略写其余"纪律的落点，避免每个维度写成同样厚度的流水账。

## [五…N、按品类挂载的维度块 —— 见下方菜单]

## 末章、总结与启发（作品集/面试的重头戏）
- 这款游戏在设计上做对了什么、做了哪些取舍
- **可迁移的设计方法**：我从中提炼出什么、能用到什么品类/项目
- 如果让我来优化，我会改什么、为什么（展示主动设计能力）

## 附、信息来源与不确定项（固定结构，见本文件第三节）
```

每个挂载块都按 **现象【事实】→ 设计意图【为什么】→ 评价/可学之处** 的逻辑写，而不是只描述现象。

---

## 二、可挂载维度块菜单（按品类取舍）

> 取舍依据是 `by-genre.md` 的权重表（◎○△✕）：**权重决定挂不挂，本菜单给出挂载形态**。两处改动时保持同步。

| 维度块 | 适用品类（簇） | 不适用时 |
|---|---|---|
| 商业化（付费点地图/付费深度分层/付费墙） | C 养成、G 休闲、MMO；F 簇限外观通行证 | 买断制只写"买断+DLC/章节解锁"一句带过；纯单机可砍 |
| 经济 / 资源水池 | C 养成、D 模拟、G 休闲、MMO | 无长线资源循环的品类直接砍 |
| 数值与成长 | C 养成、ARPG、SLG | E 内容体验簇砍 |
| 情绪 / 体验曲线 | E 内容体验、叙事/恐怖、单机剧情向 | 纯竞技/休闲可砍或并入"玩法" |
| 关卡 / 难度曲线 | A 操作、E 解谜/平台、塔防 | 开放养成型可弱化 |
| 平衡性 | B 策略、F 社交竞技 | PvE 单机砍 |
| UGC / 社区生态 | 沙盒、MMO、强 UGC 游戏 | 无 UGC 砍 |
| 社交系统 | F 社交竞技、MMO、SLG | 单机砍 |
| 新手引导 FTUE | 系统复杂（D 模拟、C）、休闲泛用户 | 极简上手品类一句带过 |
| 题材与表现层 | 视情况（落到"它服务了什么设计目标"，别写成审美点评） | — |

**挂载示例**：
- 二游（C 簇）：商业化 + 经济水池 + 数值成长 + 留存 + FTUE。
- 买断动作单机（A 簇）：玩法/战斗 + 关卡/难度曲线 + 情绪曲线 + 表现层；**砍掉商业化与经济水池**。
- 叙事解谜（E 簇）：情绪/体验曲线 + 叙事结构 + 关卡/难度梯度；数值/经济/留存/商业化基本全砍。
- 模拟经营（D 簇）：经济闭环平衡 + 系统结构 + 是否有无脑最优解 + FTUE；商业化视是否 F2P 决定。

## 三、信息来源与不确定项（报告末尾固定结构）

无论什么品类、什么深度，`full` 报告末尾都用这套固定结构收口。它把全文的【事实/推断/假设】标注汇总成可核查的清单，对 live-service 游戏尤其重要（数据变化快，访问日期是可信度的一部分）。

```markdown
## 附：信息来源与不确定项

### 已验证事实
- （游戏内明确呈现 / 官方确认的关键结论，逐条列）

### 推断依据
- （每个关键【推断】对应的信号链：我看到什么→所以推断什么）

### 未确认假设
- （建模/估算类【假设】，明确标"未公开，量级估算"，给区间不给精确值）

### 待补信息
- （需要补充体验或数据才能下定论的空白点，诚实留白好过编造）

### 来源与访问日期
- 来源名 / 链接 — 访问日期 YYYY-MM-DD
```

`quick` 深度（对话内）可不强制完整附录，但关键数字仍必须当场标层级，绝不把推断当官方。

## 四、单点深拆模板

> 篇幅锚点：约 **1500–2500 字**，写透而非铺广。

只保留与目标维度相关的骨架章节并加深，砍掉无关块。结构：

```markdown
# 《游戏名》— [某维度] 深拆
> 版本/平台 · 单点深拆 · 日期

## 1. 这个维度在整局设计里的位置（一段，挂回核心循环）
## 2. 拆解主体（按 dimensions.md / numerical-and-economy.md 的追问清单逐层挖透）
   - 现象【事实】→ 意图【为什么】→ 模型/结构（数值经济用水池图、曲线）
## 3. 评价与取舍（做对了什么、代价是什么）
## 4. 如果我来做（替代方案 + 理由）
## 附：来源与不确定项
```

篇幅写透而非铺广——单点深拆的价值在深度，别退回成浅尝辄止的全面拆解。

## 五、竞品对比模板

> 篇幅锚点：约 **1500–3000 字**，视对比维度数量。

竞品对比的主体是**横向对比表 + 定性结论**，不做数字评分。完整的对比维度、定性分级标签（强/中/弱、适合借鉴/需改造/不建议照搬）与表格写法见 `references/comparison.md`。骨架：

```markdown
# [品类] 竞品对比：《A》vs《B》vs《C》
> 对比目的（立项/选型）· 日期

## 1. 三款定位速览（各一句话）
## 2. 横向对比（按 comparison.md 选 3–5 个真正可比的维度做表 + 定性标签）
## 3. 关键差异点逐条点评（谁的做法更适合什么场景，不简单评高下）
## 4. 对"我们要做的项目/方向"的启发（落点）
## 附：来源与不确定项
```
